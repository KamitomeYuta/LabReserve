## ทำความเข้าใจ

Primary key ระบุแถวหนึ่งแถว Foreign key เชื่อม reservation กับ user/equipment และห้ามชี้ไปของที่ไม่มี Unique constraint กัน asset code ซ้ำ CHECK start_at < end_at กันช่วงกลับด้านแม้ writer ไม่ผ่าน API

JOIN รวมข้อมูลจากตารางที่สัมพันธ์กัน DTO ของรายการจองจึงมี equipmentName โดยไม่ต้องคัดลอกชื่อไว้ทุกแถว Query ใช้ $1/$2 เป็น parameter แยกข้อมูลจากคำสั่ง SQL ไม่ต่อ string จาก input ผู้ใช้

transaction() ยืม connection เดียวจาก pool แล้ว BEGIN → ทำงานทั้งหมด → COMMIT ถ้าขั้นใด throw จะ ROLLBACK และ release ใน finally ทุก query ใน transaction ต้องใช้ client เดิม ถ้าเผลอใช้ pool.query จะอาจไปคนละ connection

## ลงมือทดลอง

คำสั่งจากรากโปรเจกต์ (โฟลเดอร์ที่มี package.json):

```bash
docker compose exec db psql -U labreserve -d labreserve -c "SELECT asset_code,name,active FROM equipment ORDER BY asset_code;"
docker compose exec db psql -U labreserve -d labreserve -c "SELECT r.id,e.name,r.status FROM reservations r JOIN equipment e ON e.id=r.equipment_id;"
```

**ผลที่ควรเห็น:** query แรกได้อุปกรณ์ demo 6 แถว; query หลังได้เฉพาะรายการที่คุณเคยจอง ซึ่งอาจยังไม่มี

**ถ้าติดปัญหา:** ตารางไม่พบแปลว่ายังไม่ migrate หรือเชื่อมผิดฐาน; database test กับ demo เป็นคนละฐาน ไม่ควรย้ายข้อมูลข้ามเพื่อทำให้ test ผ่าน

## แบบฝึกหัด

เขียน SELECT แสดงเฉพาะอุปกรณ์ active=true เรียงตาม name แล้วอธิบายว่าทำไมต้องใช้ parameter ถ้ามีคำค้นจากผู้ใช้
