## ทำความเข้าใจ

Unit tests ตรวจ rules ด้วยเวลาคงที่เพื่อจับ boundary เช่น member ยกเลิกตรงเวลาเริ่มไม่ได้ Integration tests ใช้ฐานข้อมูลจริงเพราะ mock ไม่พิสูจน์ exclusion constraint หรือ rollback ส่วน E2E ใช้ browser จริงตรวจ form และผลที่ผู้ใช้เห็น

Red–green คือเขียน expectation ที่ถูกต้องก่อน → เห็นล้มเพราะพฤติกรรมยังไม่รองรับ → เพิ่มโค้ด → เห็นผ่าน ระวัง test ที่คำนวณ expected ด้วย helper เดียวกับ implementation เพราะอาจผิดพร้อมกันและยังผ่าน

ก่อนเพิ่ม test ให้บอกได้ว่าถ้าเปลี่ยนบรรทัดไหนผิด test นี้จะล้ม เช่นเปลี่ยน >= เป็น > ที่ deadline หรือเอา ownership filter ออก แล้วตรวจ behavior ไม่ตรวจแค่ชื่อฟังก์ชันว่ามีอยู่

## ลงมือทดลอง

คำสั่งจากรากโปรเจกต์ (โฟลเดอร์ที่มี package.json):

```bash
npm test
npm run test:integration
npm run test:e2e
```

**ผลที่ควรเห็น:** unit, PostgreSQL integration และ browser tests ผ่านตามรายงาน verification ปัจจุบัน; browser fixtures ใช้ฐานแยกและ reset ก่อนทดสอบ

**ถ้าติดปัญหา:** Browser tests ใช้พอร์ต 3100; อย่าเปิด server อื่นที่พอร์ตนี้ หาก Chromium ไม่พบรัน npx playwright install chromium

## แบบฝึกหัด

เพิ่ม test ว่า admin ยกเลิกหลังเวลาสิ้นสุดไม่ได้ โดยใช้เวลาคงที่ ไม่ใช้ sleep
