## ทำความเข้าใจ

เลือกฟีเจอร์เล็กที่ยังไม่มี เช่นจองล่วงหน้าได้ไม่เกิน 30 วัน เขียน requirement ให้ชัดว่า 30 วันพอดีผ่านไหม ใช้เวลาเขตไหน และตรวจที่ server หรือ UI จากนั้นเขียน test ก่อนเปลี่ยน implementation

เก็บก่อน/หลังใน commit ที่อ่านง่าย จดสิ่งที่เดาผิด ปัญหาที่พบ และวิธีพิสูจน์ อย่าแก้ tests ให้รับพฤติกรรมผิดเพียงเพราะอยากให้ suite เขียว เปิด PR ใน repository ของคุณเพื่อขอ review เมื่อพร้อม

ในการสัมภาษณ์บอกว่า reference project นี้สร้างร่วมกับ AI แล้วชี้สิ่งที่ตนเพิ่มเอง การอธิบาย trade-off และตรวจงานได้สำคัญกว่าการท่องว่าใช้เทคโนโลยีอะไร ไม่อ้างผู้ใช้จริง SLA หรือ production experience ที่ยังไม่มี

## ลงมือทดลอง

คำสั่งจากรากโปรเจกต์ (โฟลเดอร์ที่มี package.json):

```bash
git switch -c learning/booking-horizon
npm test
git diff
```

**ผลที่ควรเห็น:** ได้ branch สำหรับงานเรียน tests เดิมผ่านก่อนเริ่ม และหลังเพิ่มกติกามีทั้ง boundary test กับ implementation ที่อธิบายได้

**ถ้าติดปัญหา:** หากมี uncommitted work ให้ตรวจ git status ก่อนเปลี่ยน branch; อย่า copy เฉลยโดยไม่สามารถอธิบาย test

## แบบฝึกหัด

เพิ่มกติกาจองล่วงหน้าไม่เกิน 30 วัน พร้อมกรณี 30 วันพอดีและเกิน 1 มิลลิวินาที แล้วอัปเดต portfolio ด้วยสิ่งที่ทำจริง
