## ทำความเข้าใจ

Docker image บรรจุ runtime กับ build artifact; container เป็น instance ของ image; volume เก็บฐานข้อมูลข้ามการ restart Dockerfile แยก build stage จาก runtime และใช้ non-root user

CI รัน check/test/build ใน environment ใหม่เพื่อลดปัญหาเครื่องฉันรันได้ แต่ไฟล์ workflow ที่เขียนไว้ยังไม่เท่ากับผลรันบน GitHub ต้อง push ไป repository ของคุณและดู job จริง ในรายงานระบุสิ่งที่ตรวจ local แยกจากสิ่งที่ยังไม่รันภายนอก

Backup ไม่พอจนกว่าจะ restore แล้วตรวจข้อมูลได้ สคริปต์ restore-check สร้างฐานใหม่ ไม่เขียนทับของเดิม แล้วเทียบ fingerprint โดยใช้ demo ที่ไม่มี writes ระหว่างตรวจ ความเร็ว local ไม่ใช่ RTO ที่รับประกัน

## ลงมือทดลอง

คำสั่งจากรากโปรเจกต์ (โฟลเดอร์ที่มี package.json):

```bash
docker compose ps
curl -i http://localhost:3000/health/ready
bash scripts/restore-check.sh
```

**ผลที่ควรเห็น:** healthy, HTTP 200 และ Restore verified พร้อมฐานใหม่/fingerprint; source ยังอยู่

**ถ้าติดปัญหา:** ถ้า fingerprint ไม่ตรง ตรวจว่ามีผู้ใช้งานเขียนข้อมูลขณะ dump หรือไม่; ห้ามลบ volume หรือ restore ทับ source เพื่อทำให้ตัวเลขตรง

## แบบฝึกหัด

เขียน incident report จำลองว่า readiness เป็น 503 แต่ liveness เป็น 200 โดยระบุหลักฐาน สาเหตุ วิธีแก้ และการป้องกันซ้ำ
