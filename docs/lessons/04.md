## ทำความเข้าใจ

HTTP request มี method, path, headers และอาจมี body GET อ่านข้อมูล POST สร้างรายการหรือทำ action PATCH แก้บาง field JSON เป็นรูปแบบข้อมูลที่ serialize ข้าม network ไม่ใช่ object ใน memory ก้อนเดียวกัน

fetch คืน Promise; await รอ response แต่ HTTP 400/409 ไม่ทำให้ fetch throw เอง api() จึงต้องตรวจ response.ok และแปลง error body เป็น ApiError ส่วน network failure อาจ throw ก่อนมี response

201=สร้างแล้ว, 204=สำเร็จไม่มี body, 400=input ผิด, 401=ยังไม่ authenticated, 403=ไม่มีสิทธิ์หรือ CSRF ผิด, 404=ไม่พบ/ไม่เปิดเผย resource, 409=ขัดกับสถานะปัจจุบัน, 500=ข้อผิดพลาดภายใน การแยก code ทำให้ UI ตอบสนองถูก

## ลงมือทดลอง

คำสั่งจากรากโปรเจกต์ (โฟลเดอร์ที่มี package.json):

```bash
curl -i http://localhost:3000/health/live
curl -i http://localhost:3000/api/v1/equipment
```

**ผลที่ควรเห็น:** health ได้ 200; equipment จาก curl ที่ยังไม่มี session ได้ 401 พร้อม JSON error และ requestId

**ถ้าติดปัญหา:** curl ไม่แชร์ cookie กับ browser การ login ใน browser ไม่ได้ทำให้ curl มี session; ตรวจ Network tab เมื่อ CSRF header ขาด

## แบบฝึกหัด

ดู request ที่จองชนกันใน Network แล้วเขียนสรุป method, status, error.code และ UI ควรทำอะไรต่อ
