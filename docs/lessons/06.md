## ทำความเข้าใจ

Express middleware ทำงานตามลำดับ app.ts ตั้ง security headers, requestId, body parser, cookie parser, CSRF แล้วค่อย route การ parse body อาจล้มก่อนถึง route จึงมี error handler อยู่ท้ายสุด

Route แปลง HTTP input เป็นข้อมูลที่ใช้ได้แล้วเรียก use case Service จัดลำดับ business operations และ transaction Repository อ่านข้อมูลที่มี shape เหมาะกับ response rules.ts เก็บกติกาที่ไม่ต้องมี database ทำให้ unit test เร็ว

ไม่จำเป็นต้องสร้าง class/controller หลายชั้นเพื่อให้ดูเป็น enterprise Equipment CRUD จึงยังมี SQL ใน routes ที่อ่านง่าย ส่วน reservation แยกเพราะมี lock และหลาย write ซึ่งมีผลต่อความถูกต้อง

## ลงมือทดลอง

คำสั่งจากรากโปรเจกต์ (โฟลเดอร์ที่มี package.json):

```bash
npm run test:integration
```

**ผลที่ควรเห็น:** ชุดทดสอบ API ผ่านโดยใช้ PostgreSQL จริง รวม malformed ID, pagination และ permission

**ถ้าติดปัญหา:** ถ้า test ต่อฐานไม่ได้ให้ตรวจ TEST_DATABASE_URL และ createdb ตาม README; อย่าแทน DB ด้วย mock เพื่อซ่อน setup ที่ยังไม่ทำงาน
